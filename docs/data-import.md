# Data import

Shared menu producers select each game's configured source and compiled clean-US
tables. The map graphics producer preserves ordered uploads into both VRAM
banks, including compression, graphics-file padding and the native WRAM tilemap
destinations. Runtime presentation reads these generated bytes; it does not
substitute another game's artwork or synthesize tables to satisfy a reader.

Link/item producers resolve each pack's graphics, OAM and finite animation
pointer streams against its compiled symbols. Graphics indices and OAM banks
are pack-specific, even when an action has the same update boundaries. Only
native pose families are emitted. Sword-clink lists end at their native zero
bytes; a label boundary may be an alias or fallthrough within another list.
Readers preserve collision-set order and reject unavailable pose families.
Feather air parameters come from each configured native build. Seasons alone
emits the Cape pose family and its descending-speed threshold; Ages does not
borrow or synthesize that branch.
Common effect producers resolve each game's interaction graphics, animation,
cue and priority tables. Projectile collision data retains native mode order,
list fallthrough and directional relative pointers independently of item data.
Companion terrain probes, vine identities, collision masks and weapon attributes come from each
compiled game through a shared producer, independently of animal story scripts.
Native special-object OAM initialization retains the full ID-ordered attribute
table and publishes tile base, flags, backup and graphics-refresh marker through
the live companion owner on each executed initialization call.
Directional probes retain Y/X order and cumulative wall-probe deltas.
Vine-top collision operands and cliff comparisons retain the selected game's
tile IDs; common animal collision consumers share that imported rule.
Native special-object visuals retain partial uploads across animation loops.
A repeated bytecode position can produce a different picture until its graphics
selection and retained VRAM also repeat. Visual readers do not require story
scripts to load these native graphics and OAM records.
Moosh's finite fall/stomp streams end at the bit7 signal consumed by its native
handler; the animation reader must not decode the following unrelated bytes.
Its water-hover hazard, lifetime and exclamation offset come from the selected
compiled body handler, independently of Ages' rescue event.
Ricky's common body/item parameters likewise come from each native build;
its vine comparison retains the game's tile index. Ages' departure parameters
belong to a separate content binding and do not supply Seasons behavior.
Compiled symbol lookup preserves bank and case. A ROM byte read with an
ambiguous label must supply its source bank owner; identical handler names
in different banks must not select whichever row appeared last in the symbols.
Animal mouth eligibility and effects reuse the full native collision tables;
story producers do not duplicate their masks or individual columns.
Directional debris keeps each pack's OAM offsets and terminal markers even
when both builds refer to the same common sprite sheet.
Bomb and carried-object producers resolve each native build's item graphics,
animation/OAM aliases, lift timing, weights, offsets and landed-hazard signal.
Shared artwork or identical timings do not permit borrowing another pack's
graphics indices or collision identity. Bomb movement reads the selected
pack's common item-cliff data rather than exporting a second passability list.
Satchel and Pegasus producers resolve both native builds independently,
including effect-table rows, animation aliases and fallthrough, signed loop
targets, the game's initial bounce byte, and selected parent rejection gates.
Swimming rejects Satchel use in both games; raft and underwater rejection are
retained only where the native parent has those checks. They do not require the Ages
Shooter parent record to construct a Satchel child.
Gale, falling-arrival and Flute Link frames belong to the shared Link
presentation producer. It retains
partial graphics uploads across consecutive frames before resolving OAM cells;
gameplay does not load a pregame story database to animate these states. Fall
landing records preserve each build's tile-read and trampoline dispatch, including
the clean-US Ages omission. Attached burning
effects likewise use each native build's PART animation and OAM aliases.
Boomerang variants retain each pack's compiled attributes, finite animation/OAM
stream and exact uncompressed weapon-upload bytes. The level-2 upload uses its
native source offset and palette; it is not a recolored level-1 texture. The
shared graphics cache decodes these immutable 2bpp bytes for presentation.

Drop producers retain each game's enemy and terrain selection rows, aliased
probability masks, availability bytes, Subrosia remapping and reward parameters.
Graphics IDs and OAM banks are native to the selected pack, including common
artwork reached through different indices.
Enemy identity catalogs resolve the configured native constants and dispatch
pointers against compiled tables. A catalog row classified as unimplemented
provides a source identity for tooling; it does not imply imported AI, graphics
or support for every handler-specific subid.
Enemy definitions retain compiled subid continuation bits and last-row reuse.
Aliased animation streams are bounded by the poses the native handler can
select; an additional pose used by another alias does not expand its states.

Object collision producers retain each game's complete mode matrix, enemy/PART
active masks and native initial item/target collision identities. Source rows
are checked against compiled bytes, including `dbrev` bit order. Item-specific
readers must query this pack-bound matrix rather than export separate copies or
assume Ages' column numbers and table extents. Common damage-status exports
require matching compiled values in both games.
Common enemy recoil, hazard, steering and projectile-bounce profiles are
published once only after both configured sources and compiled US operands pass
the same contract.
Species tables do not duplicate those profiles. Native recoil-dust animation,
terminal parameter and graphics belong to the common effects producer for each
pack, independent of NPC imports.
Common enemy-family producers resolve each game's compiled graphics headers,
properties, animation pointers, relative loop targets and OAM records. Family
readers consume their scoped native definitions and shared behavior tables.
Shared code does not imply equal numeric graphics or collision IDs. Death-puff
producers verify native terminal parameters and retain the frames preceding
them; they do not depend on a game's NPC or enemy-story bundle.

## Boundary

The importer converts the supported ROM and `oracles-disasm` sources into
address-independent runtime assets in game packs under `assets/oracle/`. The
current entry point generates Ages plus the Seasons launcher, frontend menus,
opening, inventory presentation, overworld, Subrosia and admitted side-view layouts for
navigation. Dungeon floor layouts and metadata use one importer for both games,
checked against their compiled native pointers and property bytes. Each pack
has its own table manifest; table/cache identity includes the full pack path.
The `common` pack contains normalized engine contracts and source tables whose
compiled bytes are checked against both supported ROMs before sharing them.
Production runtime
code consumes those assets and never opens assembly files.

Sign and chest producers follow each game's compiled group pointers, including
aliased groups, and verify every source row and terminal byte against the ROM.
They resolve text aliases, page commands, treasure properties and BCD amounts
from the selected pack. Shared runtime readers validate their schemas; native
table extents belong to the importer and independent ROM regressions.

Dialogue reference expansion shares one execution-order resolver: calls retain
their return suffix, jumps terminate it, and physical fallthrough follows the
imported entry boundary. Preserve positions and formatting through expansion;
dynamic calls remain with their runtime owner. Script stages use the shared
command compiler for ordinary operations and explicit bindings for native
helpers, retaining source-specific guards and copied-WRAM jump timing.

Seed-tree refill records retain native history order and a separate flag-bit
index. Ages' sixteen histories and Seasons' eight histories use different bit
orders; consumers must not infer the flag bit from the row index. Room object
streams likewise retain source order and conditional pointers, including
branches whose runtime handlers are explicitly unsupported.
Enemy admission metadata is projected from these native instructions and labels;
it does not require a second placement table or an address-binding table.
Live allocation and conditional execution remain owned by the native stream reader.
Seasons opening scenery retains the native tilemap writes, collision overrides,
and source PNG polarity, including opposite encodings within chained OBJ sheets.
Inventory display selectors retain their source field, pointer order and level
bias. A biased pointer's preceding record is retained for a zero level rather
than clamping the index. Graphics headers retain destination bank/tile,
upload order, PNG encoding properties and native palette writes; no menu must
borrow another game's layouts or item tables.
Screen-transition records retain seasonal tileset indirection, ordered unique
graphics uploads and palette commands. Smooth palette routes retain the native
game's season lookup or flag gate; a shared room number does not imply a shared
palette route.

The output root must contain only current generated packs and Godot import
metadata. When changing the pack layout, start with an empty output directory
and regenerate; preserve or remove obsolete generated output directly rather
than adding legacy cleanup behavior to the importer.

The `external/oracles-disasm` submodule pins the vanilla `master` disassembly
at the supported reference revision, `842c5649b63f5b6fae8ffd55f80f45f86e9c10e7`.
Initialize it with `git submodule update --init --recursive`. This default path
is relative to the project root and resolved from the script's location
regardless of the working directory. Keep the pinned revision for reproducible
imports; updating it requires reviewing generated differences and rerunning
verification. `external/.gdignore` keeps source assets outside Godot's resource
scan and exports.
The import submodule is never built or modified. Without `-Rom`, the shared
ROM resolver builds separate checkouts using `tools/rom-build/ages.json` and
`tools/rom-build/seasons.json` and caches verified images under `.cache/oracle-rom/`.
Both games require matching assembler symbol files: script addresses and
shared WRAM bindings come from assembled labels rather than address comments.
The ROM-build revision
is intentionally independent of the import revision, matching the proven CI
recipe. A warm cache requires no build tools or network; concurrent callers
share a build lock, and failed builds are retained for diagnostics without
publishing an unverified image. `hack-base` is not a supported input: its
expanded tilesets and CROSSITEMS behavior differ from the original game.

Vanilla shared layout headers are resolved into per-tileset mapping/collision
files, and clean-ROM main and unique graphics uploads compose each atlas in
original order. Room-dependent cliff palette changes remain in the room loader,
where the effective tileset flags and active room byte are available.
Shared room and dungeon-layout labels are expanded for every alias; a fresh
output directory receives all 1,536 room layouts.

The stable entry point validates the clean US ROM before doing any work:

```powershell
& .\tools\import_oracles.ps1
& .\tools\import_oracles.ps1 -Rom 'D:\roms\ages.gbc' -Disassembly 'D:\src\oracles-disasm'
```

Expected MD5: `C4639CC61C049E5A085526BB6CAC03BB`. An explicit `-Rom` bypasses
the builder and cache but must pass the same size and hash checks. A different
ROM must fail; bank addresses and source data are not interchangeable.

Seasons uses the pinned WLA rebuild hash in `tools/rom-build/seasons.json`.
The upstream disassembly's README documents that WLA builds differ from the
Seasons cartridge hash in unused space. `-SeasonsRom` overrides that image;
the matching pinned symbol file is still resolved for import. An Ages `-Rom`
override therefore does not remove the Seasons build/cache requirement.

The generated `common/metadata/wram_fields.tsv` binds each source symbol to its
address in each game. Shared typed save/runtime access uses the symbol and an
explicit array offset; missing game-specific fields read as unowned and reject
nonzero writes. Native scripts retain physical addresses. Runtime snapshots
retain their game and reject cross-game restoration before changing memory.
Graphics uploads
past an individual source image's end use the pinned ROM's actual adjacent
bytes; they must not be padded or silently truncated.

On Linux, install PowerShell 7, the .NET 8 SDK and the ROM build dependencies
listed in [Development](development.md#requirements), then invoke the same entry
point with `pwsh -NoProfile -File tools/import_oracles.ps1`. ROM and disassembly
overrides accept native Linux paths. Windows PowerShell 5.1 remains supported.

## Import organization

`tools/import_oracles.ps1` is the authoritative ordered list of import stages
and their `ImportStageContract` declarations. `tools/import_oracles/` contains
`Shared/` infrastructure/normalization and per-game feature stages. The Ages
source configuration supplies the clean-US assembly symbols explicitly;
`tools/OracleImporter/` contains the typed assembly source model and shared
parsing infrastructure. A producer may read common assembly while binding
game-specific tables; that does not make its whole stage game-independent.
Sprite names can identify different artwork in each game. Resolve these names
against the selected game's directory, then common graphics.

Shared transformation and swimming producers resolve graphics, animation and
OAM pointers against each game's native build. A common state machine does
not permit fallback to another game's sprites or table IDs. Common Flippers
and diving records are separate from Ages-only Mermaid parameters, so loading
the common swimming data does not require an unsupported game feature. This
also applies to side-view swimming: each pack supplies its Flippers frames;
only Ages supplies Mermaid frames. Shared air and effect producers own the
side-view physics and bubble records independently of story and NPC imports.

Each stage declares its variable and helper inputs and outputs and runs in its
own PowerShell module scope. The runner supplies only declared inputs and common
helpers, rejects unbound variables, and publishes only declared outputs. Exported
helpers retain their owner's private state and helper functions; shared input
collections retain their identity and original mutation order. A stage cannot
consume another stage's locals merely because it ran earlier. Put new data in the
stage that owns the source domain; add a stage only when it has a distinct
ownership boundary.

The assembly source repository is the only component allowed to read `.s`
files. It retains ordered nodes, aliases, source spans, and actionable parse
errors. Feature importers interpret those nodes; they should not rebuild ad hoc
regex parsers over raw lines when the shared model can represent the syntax.
Files are parsed independently, so the configured clean-US symbol set also
includes the `ENABLE_US_BUGFIXES` symbol derived by `constants/common/version.s`.
Scoped structured queries select exactly one active label definition for that
configuration and stop at the next active label boundary. Inactive definitions
remain available through the source metadata; they do not truncate compiled
table or instruction queries. Two active definitions are still an error.

## Generated-data contract

Generated outputs are deterministic build artifacts, not hand-maintained
content. Every table or binary format must have:

- one owning importer stage and one runtime reader;
- stable source order unless the original format defines another order;
- a schema version or exact length contract;
- strict parsing of IDs, widths, sentinels, aliases, and duplicate keys;
- source-aware diagnostics that identify the original path, label, row, or
  address;
- an entry in the generated-table manifest when applicable.

Use the shared generated-table writer and reader for TSV data. Preserve empty
cells and escaping; do not split rows independently in feature databases.
Treasure-object rows retain the original flags byte as well as the item,
parameter, text and graphics. Native producers derive spawn mode, grab mode
and room-item marking from that byte; receiving an item is not sufficient
evidence for substituting another presentation or persistence policy.
Generated tables and verification manifests use UTF-8 without BOM and LF
newlines. Generated opaque grayscale PNGs use the importer host's portable
writer, with stored DEFLATE blocks to keep Windows and Linux output identical.
Tile placement, shade inversion and dimensions remain owned by their import
stages; no platform image API or external image package is required.
Binary readers validate exact expected byte counts or explicit format versions.
Packaged binary inputs and schema-neutral TSV tokens are cached for the session
and can be prepared by the startup I/O worker. Binary consumers receive copies,
so live layouts cannot modify the cached inputs. Parsed tables are retained by
their complete schema contract; first use still validates manifest hashes,
versions, headers, key rules and row counts. Changing generated files requires
restarting the running game.
When a format changes, update its importer, runtime reader, manifest expectation,
and regression in the same change.

Generated paths are runtime APIs. Rename or remove one only after updating all
readers and validations. Never repair an output in `assets/oracle/` directly.

## What to import

Import source facts that the runtime needs to reproduce behavior: ordered
placements, tables, constants, animation/OAM data, state predicates, script
commands, and source identity. Keep procedural behavior in runtime code when
the original behavior is a handler or state machine rather than data.

Prefer typed records over clone-side inference. For example, import the exact
predicate operands that control an interaction instead of importing a vague
`visible` boolean derived for one save state. Conversely, do not encode a C#
state machine as a huge generated instruction table unless the original is
itself a script stream.

Unsupported source input must stop import or startup with actionable context.
Do not silently drop an unknown directive, command, object, treasure mode, or
table branch.

Animation labels are entry points, not implicit terminators. Trace whether the
handler keeps advancing a stream across the next label or stops on a frame
parameter/held pose. Executed fallthrough must retain its following frames and
interior loop target; a one-time intro must not repeat on subsequent loops.
An animation parameter such as `$ff` signals its caller; preserve a following
loop when the handler continues animating instead of deleting the object.
The enemy-definition importer accepts the traced animation indices that require
this complete stream, separately from its existing declaration-bounded records.

## Adding or changing imported behavior

1. Trace the source table, pointer aliases, consumers, and original ordering.
2. Decide which stage owns the records and whether the shared source model
   needs a new syntax capability.
3. Define the smallest typed output schema that preserves required source
   identity and semantics.
4. Add strict importer checks, including malformed and unsupported cases.
5. Update the runtime reader and reject stale versions, counts, or operands.
6. Add importer/unit coverage and a gameplay validation that consumes the real
   generated data.
7. Regenerate assets and review every unexpected output change.
8. Prove deterministic output:

```powershell
& .\tools\verify_oracle_import.ps1
```

The verification script runs ownership checks and importer tests, builds the
importer once, then checks byte parity using two concurrent import processes.
One refreshes `assets/oracle/`; the other writes to a fresh temporary directory.
Stages remain ordered within each process, with separate source hosts and caches.
Existing non-generated files in `assets/oracle/` must not be present (Godot
`.import` metadata is ignored), since they would fail parity with a fresh import.
Use `-Workers 1` to check two consecutive imports into `assets/oracle/` instead.
`-TimeoutSeconds` defaults to 600 per worker batch; zero disables the deadline,
as used in CI. ROM cache-lock waits likewise accept `-LockTimeoutSeconds 0`.
Failures retain logs and
manifests at the printed temporary path; successful runs clean them up.

The importer accepts `-OutputDirectory` for isolated output and `-SkipBuild`
when the optimized Debug importer host has already been built. Normal imports
still build the host and write to `assets/oracle/` by default. `-Profile` prints
individual stage and cache-check timings; every successful invocation reports
its total time and whether it generated assets or reused a verified import.

Unchanged imports can reuse a completed result recorded under
`.cache/oracle-import/`. Reuse requires matching content hashes for the ROM,
disassembly inputs (including graphics, binary files and properties), importer
code, selected symbols, all linked source files, compiled host, build configuration and
PowerShell/.NET execution environment.
Every generated output is also checked for content and presence; unexpected
files invalidate reuse. Godot `.import` metadata is excluded. An output lock
prevents concurrent imports from owning the same destination, and cache metadata
is published atomically only after success and a second input fingerprint check.
Missing, changed or corrupt cache data triggers complete generation.

Use `-Force` to execute every stage even when inputs and outputs match:

```powershell
& .\tools\import_oracles.ps1 -Force -Profile
```

The import verifier always forces both complete imports, including its serial
mode. Cache reuse does not replace stage/schema checks or deterministic-output
verification. The typed source host owns indexed node-range and source-line
queries, preserving active branches, source order and occurrence selection.
Companion indices retain animation fallthrough, loop boundaries and raw OAM;
animation-specific VRAM resolution still starts fresh for every animation.

Finish with the normal build and full headless suite from
[Validation](validation.md).
